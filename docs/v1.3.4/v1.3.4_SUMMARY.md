# v1.3.4 修正内容サマリー

## Perplexity.ai の対応 (PR #7)

Perplexity にて、拡張機能有効時に「Enterで送信されてしまう（改行できない）」「Cmd+Enter などの一部ショートカットが効かない」不具合を修正しました。

### 1. `perplexityAdapter` の新規追加
- Perplexityが使用している Lexical エディタ（`#ask-input`）を正確に検知する専用の SiteAdapter を追加しました。
- Lexical エディタに対して汎用的な `document.execCommand` ではなく、 `Shift+Enter` のキーイベントを発行することでネイティブな改行処理を誘発するようにしました。（コントリビューター @derrabe による実装）

### 2. コアロジックの改善 (`nativeSendKey: 'none'`)
- Perplexity は元々サイト側で `Cmd/Ctrl+Enter` での送信をネイティブサポートしています。
- これに配慮し、拡張機能からは送信キーのハンドリング（ボタンクリックの捏造など）を**一切行わず、Enterキーの改行ブロックのみを担当する**新しいモード `nativeSendKey: 'none'` を実装しました。
- この改修により、Windows と macOS の両環境で、Perplexity本来の `Cmd/Ctrl+Enter` 送信ショートカットがそのまま活かされるようになりました。

## 3. 回帰防止のためのユニットテスト追加
- `nativeSendKey: 'none'` （ネイティブ送信アプリ）設定時の挙動を保証するため、 `src/content/keyClassifier.ts` に対するユニットテストを追加しました。
- 以下のケースが正常に動作し、既存の送信ロジックを壊していないことを確認済みです：
    - IME 入力中の Enter が無視されること。
    - プレーンな Enter が `newline` （改行）として判定されること。
    - Mac での Cmd+Enter が `ignore` （アプリ側のネイティブ送信に任せる）として判定されること。
    - Windows/Linux での Ctrl+Enter が `ignore` （アプリ側のネイティブ送信に任せる）として判定されること。
